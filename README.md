# 지구과학 데이터 탐구 프롬프트 워크시트

2022 개정 교육과정의 성취기준과 탐구 활동을 살펴보고, 학생이 데이터 분석 결과를 직접 검증하도록 돕는 정적 워크시트입니다. 입력한 응답은 현재 브라우저의 로컬 저장소에만 보관되며 연구자나 외부 서버로 전송되지 않습니다.

## 교육과정과 활동 범위

- 통합과학1·2, 지구과학, 지구시스템과학의 **성취기준 62개에 활동 63개**를 연결했습니다. 기존 21개를 유지하고 42개를 추가했으며, 논문의 대표 사례만으로 제한하지 않습니다. 통합과학의 물리·화학·생명과학 영역도 포함합니다.
- [교육부 고시 제2022-33호](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=141&boardSeq=93458&m=0404)의 **[별책 9] 과학과 교육과정** HWP와 62개 성취기준을 대조했습니다. `[12지구01-03]`의 “위상 영상”은 고시 원문 표기를 보존하고, 실제 활동은 관련 성취수준에 따라 위성 영상을 사용함을 화면에 설명합니다.
- 성취기준은 교사 상세 화면, 모든 버전의 학생 화면 상단, A의 조립 프롬프트, 내보낸 기록에 포함됩니다. B·C는 학생이 직접 프롬프트를 작성합니다.
- 빙하 코어 활동의 기존 ID `es-0202`와 바로가기 코드는 유지하되, 연결 기준을 기후변화 `[12지구01-06]`으로 바로잡았습니다. 기별 지질시대·지층·화석 `[12지구02-02]`에는 새 활동 `es-0206`을 연결했습니다. 같은 기준의 복수 활동은 교사 화면의 활동 선택 상자에서 고릅니다.
- 활동별 자료는 **공개 관측 / 학생·교사 실험 / 공개 문헌의 표 / 교사 제공 모형**을 구별합니다. 실험·모형 활동은 교사가 실제 자료를 준비해야 하며, 앱에 측정값이나 가상의 결과를 자동으로 만들어 넣지 않습니다. 외부 자료의 이용 조건·계정·메타데이터는 수업 전에 확인하세요.
- 하나의 활동이 성취기준 전체의 달성을 보장하지는 않습니다. 자료 분석 외에 기준이 요구하는 개념 설명·논증·모형·토의·발표도 확인해야 합니다. 63개는 이 배포본의 활동 목록이며, 가능한 모든 탐구 주제의 완전한 목록이라는 뜻은 아닙니다.

## 교사 검토와 설문

교사 화면에서 성취기준과 활동을 선택하고, **8개 단계 비교표의 A·B·C 단계 열기**로 같은 단계의 지원 차이를 비교합니다. 상단 ‘교사’를 눌러 돌아옵니다. 개인 검토 체크는 브라우저에만 저장되며 설문 응답이 아닙니다.

KACE 투고본 표 3의 구조를 다음과 같이 반영했습니다. 비계 버전 A·B·C는 성취수준 A~E와 무관합니다.

| 단계 | A · 강한 비계 | B · 중간 비계 | C · 약한 비계 |
|---|---|---|---|
| §0 역할 선언 | 완전한 역할 템플릿 | 핵심 빈칸 | 선언 기준만 제공 |
| §1 탐구 문제 | 질문 4개 + 빈칸·자유 작성 | 질문 2개 + 자유 작성 | 질문 기준 + 자유 작성 |
| §2 데이터 맥락 | 모든 필드·변수·단위·설명 | 핵심 필드·단위 직접 확인 | 자가 체크리스트·자유 기술 |
| §2.5 예측 | 예측 표 + 근거 작성 틀 | 예측 표 | 자유 예측 |
| §3 프롬프트 | 선택·빈칸으로 자동 조립 | 질문 유형·요소 카드 | 평가 기준·자유 작성 |
| §4 검증 | 공통 5개 + 모든 활동 항목·상세 설명 | 공통 5개 + 주요 활동 2개·간단한 설명 | 직접 만든 검증 기준 3개 |
| §5 수정·반복 | 수정 문장 틀·구조화 기록 | 축약 안내·기록 | 자유 재검토 기록·수정 프롬프트 |
| §6 성찰 | 체크리스트 + 개방형 성찰 | 개방형 성찰 | 최소 안내·자유 성찰 |

‘정리’는 별도 내보내기 화면으로, 설문의 아홉 번째 평가 항목이 아닙니다. 투고본의 §0~§7 표기와 §0~§6(§2.5 포함) 표기는 앱에서 후자의 **8개 단계**로 통일했습니다.

§4는 §2.5의 예측(경향·그래프 모양, A는 과학적 근거 포함; C는 자유 예측), 결과 기록·예측 비교·모든 검증 판정과 근거가 있어야 진행됩니다. 문제·모름 또는 예측 불일치가 남으면 §5 → §3 → §4로 돌아가고, 모든 판정이 ‘맞음’이며 예측과 일치하면 §6으로 갑니다. 일치는 정확성의 보증이 아니고 불일치는 오류의 증거가 아닙니다. 원자료·계산·개념을 재검토하고, 예측 자체가 잘못되었다면 이유를 기록한 뒤 수정합니다. 재실행 전 검증은 이력으로 남기고 새 검증 판정은 초기화합니다. 미완성 기록도 ‘정리’에서 저장할 수 있습니다.

설문 버튼은 설정된 Google Forms를 새 탭에서 엽니다. **웹앱은 외부 설문의 문항을 생성·수정하거나 응답을 대신 제출하지 않습니다.** 배포 전 연구자가 다음을 확인해야 합니다.

1. 외부 폼에 승인된 연구 설명·동의와 참여 조건이 있는지 확인합니다.
2. 8개 단계별 관련성 4점 평정(1 전혀 타당하지 않음 ~ 4 매우 타당함)과 내용 타당도·실무 적합도·명확성·실용성 개방형 의견 문항을 준비합니다.
3. 1·2라운드의 기간·폼·배포 버전을 구분합니다. 2라운드의 집단 통계·본인 응답 안내는 연구자가 별도로 제공합니다. AI 오류 실험 결과는 검토 화면에 노출하지 않습니다.
4. 현재 앱은 학생 응답 수집 서버·학생 응답 대시보드·CVI 분석을 제공하지 않습니다. 외부 설문 수집·동의·보관은 외부 폼과 연구 절차에서 관리합니다.

## 로컬에서 미리보기

`type="module"`과 JSON `fetch()`를 사용하므로 `index.html`을 파일 탐색기에서 직접 열지 말고 로컬 웹 서버로 실행합니다.

1. VS Code에서 이 폴더를 엽니다.
2. Extensions에서 **Live Server** 확장을 설치합니다.
3. `index.html`을 오른쪽 클릭하고 **Open with Live Server**를 선택합니다.

## 설정 바꾸기

`js/config.js`에서 다음 값을 수정합니다.

- `appVersion`: 화면 하단에 표시할 검토 버전
- `surveyUrl`: 교사 화면의 **설문 참여하기** 버튼 링크. 빈 문자열이면 버튼이 표시되지 않습니다.
- `researcher`: 화면 하단 연구자 표시
- `contact`: 문의 이메일. 빈 문자열이면 문의 링크가 표시되지 않습니다.

설문 링크는 교사가 버튼을 눌렀을 때 새 탭에서 열립니다. 이 프로그램에는 분석, 쿠키, 로그인 또는 외부 입력 전송 기능이 없습니다.

## 활동 내용 편집

기존 활동은 `data/activities.json`, 추가 활동은 `data/activities-extra.json`의 JSON 배열에 있습니다. 앱은 두 파일을 함께 읽으며 ID는 두 파일 전체에서 고유해야 합니다. ID는 수업 링크를 위한 식별자이고 성취기준 연결은 `code`를 기준으로 합니다. 항목은 다음 구조를 사용합니다.

```json
{
  "id": "es-0105",
  "subj": "es",
  "code": "12지구01-05",
  "title": "활동 제목",
  "questions": ["예시 질문"],
  "data": {
    "name": "자료 이름",
    "org": "자료 제공 기관",
    "url": "https://example.org",
    "how": "자료를 내려받는 방법"
  },
  "vars": [{ "n": "변수 이름", "u": "단위", "r": "일반적 범위" }],
  "tasks": ["분석 작업"],
  "chart": "권장 그래프",
  "predict": "예측 안내",
  "checks": [{ "t": "검증 기준", "h": "검증 힌트" }],
  "pitfalls": ["주의할 점"]
}
```

기존 항목을 편집할 때 `id`, `subj`, `code`를 포함한 필드 구조를 유지하세요. `alignment`로 성취기준과의 연결 범위·보충할 요소를 기록할 수 있고 `tip`은 선택 사항입니다. `standards.json`은 성취기준 원문, `levels.json`은 성취수준과 관련 활동 자료이므로 JSON 문법과 원문을 보존해야 합니다. 수정 뒤에는 Live Server에서 페이지를 새로고침해 결과를 확인합니다. 예전 단일 HTML 진입 파일은 웹 서버에서 최신 `index.html`로 이동합니다. `reference/worksheet.html`은 보존용 원본이며 배포 진입점이 아닙니다.

## 검증

Node.js 24 이상에서 추가 패키지 없이 실행합니다.

```powershell
node --test tests\worksheet.test.mjs
```

활동·성취기준 연결, 63개 활동의 수업 코드, 질문 4개, 8개 단계 구분과 검증 분기의 필수 조건을 확인합니다. 브라우저에서는 각 버전의 단계별 UI, 검증 차단, 수정 재실행, 로컬 저장과 기록 내보내기도 확인하세요.

## GitHub Pages 배포

1. GitHub에서 새 저장소를 만듭니다.
2. 이 폴더의 사이트 파일과 `css/`, `js/`, `data/` 폴더를 저장소에 올립니다. `index.html`이 저장소 루트에 있어야 합니다.
3. 저장소의 **Settings → Pages**를 엽니다.
4. **Build and deployment**의 Source를 **Deploy from a branch**로 설정합니다.
5. Branch를 **main**, 폴더를 **/(root)**로 선택하고 저장합니다.
6. Pages가 표시하는 배포 주소를 열어 데이터가 정상적으로 로드되는지 확인합니다.

## 학생용 바로가기 링크

활동 ID에서 하이픈을 빼고 버전 문자를 붙인 코드를 URL 해시로 사용합니다. 배포 주소 뒤에 `#`와 수업 코드를 붙이면 해당 활동이 학생 화면으로 바로 열립니다.

```text
https://<사용자명>.github.io/<저장소명>/#es0105a
```

수업 코드는 대소문자를 구분하지 않으며 하이픈을 생략할 수도 있습니다. 예: `ES0105-A`, `es0105a`, `ess-0303-c`.

## 브라우저 저장

마지막 화면은 `evc:last`, 활동별 응답은 `evc:<활동ID>:<버전>` 키로 브라우저 로컬 저장소에 저장됩니다. 브라우저 데이터를 지우면 저장된 워크시트 응답도 삭제되므로, 제출 전에 정리 단계에서 복사하거나 텍스트 파일로 저장하세요.
